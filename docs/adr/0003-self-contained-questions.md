# 问句自含判法、规则组化为编号数组

v0.6.2 立两层之形：`_questions` 库唯存问句文本（instructions/criteria），判法（blockWhen/threshold/message）分居各组规则对象，以 `question` 引线缝之。2026-09 烤问中业主直诘「为何不径写 Q00x 编号即足」，且实证 Q008 一问四条规则（W6/L4/C4/RV3）问、向、阈、文案四同，纯系拷贝。遂于 v0.8.0 改 schema：

1. **问句自含**——`_questions` 每条 = 问（instructions＋criteria）＋判法（blockWhen/threshold/message）同居一处。
2. **规则组化为引用**——各 agent 组与 `_all` 的 `rules` 为问句编号字符串数组（如 `["Q001","Q002"]`）；全局与组引并集去重（全局在前）。同 id 即同问同判，旧「agent 顶替」语义随内联规形并废。
3. **旧形不兼容**——`{id, question, ...}` 对象规则与内联 instructions 规形不再加载（非字符串/悬空编号静默忽略，fail-open）。

**同问异参之归并通则**：归并旧规则遇判法不一时，取**最易通过**者，宁宽勿枉（fail-open）——above 取大阈、below 取小阈（拦区最窄）；文案并为通用辞。向性相左属病态，持回人工。v0.8 迁移时五组复用问参数本皆全同，唯 Q010/Q012 文案有角色微差，依通则统一。

## Considered Options

- **问句库条目内联判法（取）** vs 保留两层加默认继承（否：引线、逐字段合并、悬空回退、撞名顶替诸机制皆由此生，复杂度全在治自造之冗余）。
- **保留同问异阈之口**（否：实档无真实异阈需求，封之使一问一判、组唯选择适用与否；异判即当异问，分立编号）。
- **旧形双轨兼容**（否：契弃繁从简，解析器只认一形；本机配置随版迁移、有备份）。

## Consequences

- **破坏性（v0.8.0）**：v0.7 配置须迁移方生效（未迁移则规则项非字符串被忽略，等同零拦截——fail-open 而非报错）。
- audit/training 之规则标识即问句编号（旧 R1/W2 之号隐去，径显 Q001/G001）。
- 配置直观：读一问即见其判法；新增 agent 组唯列编号，无判法拷贝漂移之虞。

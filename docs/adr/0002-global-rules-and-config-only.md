# 全局规则组 `_all` 与规则唯存配置档

派单合规规则初版按 agent 分组，且代码内建 delegate R1–R4 作配置档缺/坏时之兜底。2026-09 烤问定案，行二变：

1. **配置档新增顶层保留键 `_all`**——全局规则组，凡派单皆受查（含无专属组之 agent，其 state 述语写死为 `"a sub-agent"`，不开配置口）；与 agent 专属组并集求值、一次请求。规则 id 相撞时 agent 专属静默优先（fail-open）；约定全局规则号与问句号以 `G` 冠之（`G1`…/`G001`…），约定入样例与文档，不入码强制。
2. **内建规则整体废除**——规则唯存配置档（经 subagent-jev skill 创建或用户手书），档缺/坏即零规则全放行。

缘由：全局组使「凡 agent 皆守」之基线规则有所归，堵「未配置即畅行」之阙；废内建使行为全归用户所有、fail-open 彻底无歧义——旧制「档坏退回内建 delegate」之半兜底，反成无人记得之隐式行为。

## Considered Options

- **范围**：唯已配置组叠加全局规则（否，「未配置即畅行」之阙犹存） vs 一切派单皆查（是——「所有 subagent 都遵守」之本义）。
- **撞 id**：逐字段合并 / 整规替换 / 禁同约定——取禁同约定（G 前缀区隔），万一相撞则 agent 专属静默优先。
- **未配置 agent 之描述**：解析 pi-subagents 四源注册表取真描述（否——为一段描述文字耦合他包 internals，不值） vs 写死通用述语 `"a sub-agent"`（是——全局规则本应 agent-agnostic）。
- **内建存废**：内建 `_all` / 内建留 delegate / 全废——取全废，内建愈简 fail-open 兜底愈净。

## Consequences

- **破坏性变更（v0.7.0）**：无配置档之安装零拦截；部署须以 skill 或手书建配置档，仓中样例仅示 schema。
- 已配置组之 state 形状与阈值不变，校准资产保全；audit 溯源不劳新字段——`blocked`/`rules` 中 `G` 开头即全局规则。
